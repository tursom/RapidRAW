# Task 4 browser checks

This fixture runs the **current production** layout components and stores in Linux headless Chromium. Its Tauri host is an explicit mock. It provides front-end interaction evidence; Windows application checks and the overall task report belong to the parent session.

Run from `RapidRAW/`:

```sh
node checks/tool-layout/run.mjs
node checks/tool-layout/run.mjs --parent-frozen --freeze /tmp/tbt-tools-source-freeze.json --output checks/tool-layout/evidence/browser/chromium.json.gz
```

`PLAYWRIGHT_MODULE`, `CHROMIUM_PATH`, and `TOOL_LAYOUT_PORT` override the existing Task 3 environment defaults: Playwright `/root/.npm/_npx/dd48173ecf795e2b/node_modules/playwright/index.mjs`, Chromium `/root/.cache/ms-playwright/chromium-1254/chrome-linux64/chrome`, and Vite `127.0.0.1:9144`. No dependencies are installed. `TOOL_LAYOUT_CASE=SpeedEdit` runs matching groups for diagnosis, but partial runs cannot publish final output.

Final publication requires the explicit parent freeze flag and a matching parent hash manifest. The runner refuses to overwrite an output file. Failed runs always write outside the repository under `/tmp/tool-layout-browser-*`, even when `--output` was requested. Final evidence is [chromium.json.gz](evidence/browser/chromium.json.gz); its counts, input digest, compressed SHA-256 and quality results are in [browser-manifest.json](evidence/browser/browser-manifest.json).

## What executes

The fixture imports production `SidePanelArea`, `PanelSwitcher` / `MobilePanelSwitcher`, `CurvesPanel`, `ControlsPanel`, `Slider`, `SpeedEditOverlay`, `useKeyboardShortcuts`, and UI/editor/settings/library/process stores. It uses production CSS and dark theme tokens, `ContextMenuProvider`, and real `DndContext` with App's 5px `PointerSensor` activation distance. The DnD callback boundary mirrors App's store calls and records starts/ends; it is not the full App handler.

Tool content for Crop/Masks/AI/Presets and Info/Export/FolderTree/Tethering is explicitly marked as fixture placeholders. Each tool placeholder has three real production Slider sentinels, writing only the fixture mask's local adjustment fields. They let the SpeedEdit test distinguish whole-image targets from local targets. **They do not prove actual tool-panel rendering or narrow Masks/AI usability.** Those require the parent's full Windows application tests.

There is no mounted `App`, `EditorView`, `Editor`, or `ImageCanvas`. The fixture supplies platform/layout mode, the selected mock image, a sentinel mask and viewport-independent workspace setup. Runtime transitions call production `store.setUI`; App's own responsive detection is outside this fixture. For the singleton-strip component case only, direct fixture `setState` supplies `[Curves, Metadata, Export]` to the upper region: ordinary `setUI` deliberately rejects a custom full-desktop layout. This isolated setup is not a claim that users can customize the fixed layout.

`host.ts` installs Tauri's mock IPC/event/window boundary before component imports. LUT listing returns an empty list; settings and adjustment autosaves return `null`; unknown IPC throws and fails the run. No image is decoded or exported, no file is written by Tauri, and no AI model or backend is run. Host bootstrap records trusted mouse/keyboard events, focus, UI/editor state transitions, IPC and browser errors. Ordinary fixture setup and store API checks are labelled separately from trusted user input.

## Assertions

The complete run has 19 case groups. Every step persists its own raw `trace` slice alongside `before` / `after` snapshots and its required `trustedInputType`. A slice is captured before any later `mark(..., true)` reset, so the desktop drag-rejection step and all three tool-entry clicks retain their input and store records. A trusted step must contain raw input of that type with `phase === step.name` and `trusted === true`; the runner independently checks retained coverage again before publication. Final evidence retains all 64 trusted steps, not just the 60 remaining in the case-end buffers. Each case also keeps its trailing raw buffer in `case.trace`; that buffer may start after an intentional reset and is supplementary to the complete per-step records.

Independent read-only review confirmed all 64 trusted steps and the four formerly missing steps directly from the saved gzip. Reversing only the trace-retention additions reproduced the previous frozen runner's SHA-256 exactly, confirming that the repair did not weaken the existing assertions. The reviewer also confirmed that `run.mjs` was the only changed runtime input and all six production freeze hashes were unchanged. The manifest records this review's scope and provenance.

## Controls and provenance

The actual MasksPanel `useShallow` callback is also extracted from its AST. In full desktop it reports visible Adjustments and disables the mask waveform entry; after switching to compact Masks, stale regional `rightTop: Adjustments` no longer reports a rendered right panel. Real mobile buttons switching Adjustments/Masks change that selector accordingly. The exact Task 3 callback and helper incorrectly report Adjustments visible in the same compact state and fail the same assertion. This proves the selector used by MasksPanel; the actual waveform button and drawing are not mounted here.

The Vite plugin loads exact `33ba1eb7` UI-store and SpeedEdit-overlay source into memory, using current imported dependencies. The critical fixed-layout and mode-preservation assertions reject that store. The same trusted Contrast selection/W/D/arrow sequence against the old overlay selects a local tool target and changes fixture-local mask data; the global-owner assertion rejects it. The old overlay also rejects the off-list Whites owner assertion. Actual old ImageCanvas selector callbacks also fail the new tool-suppression assertions. These are focused baseline controls, not a complete historical application build.

The runner fingerprints all `src/`, `src-tauri/src/`, dependency manifests, build/lint/type configuration, and browser runtime files before and after execution. Final success requires an identical map, every case passing, no browser/host errors, and successful cleanup. It also verifies the six production files in the parent's supplied freeze manifest. Markdown, evidence and the parent's Windows script are excluded from the runtime digest; final manifest artifact hashes cover the browser documentation separately. Cleanup cancels fixture autosave/history debounces, releases input, exits SpeedEdit, closes Chromium and Vite, and checks that Vite's PID and port are gone.
