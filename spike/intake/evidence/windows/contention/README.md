# Windows：阶段 1 第 5 项剪贴板占用与直接读取

**Windows 本项补测已完成，阶段 1 整体仍不通过。** 本轮只增加独立实验、证据和报告修正；正式六态粘贴、输入入口和调整参数应用均未实现。macOS、资源管理器、真实 RAW、纯多图、系统截图、复制图片地址、真实网站及 PNG/WebP 拖放仍待人工补测。

## 结论与参数建议

1. **占用已直接复现。** 首次序列变化后立即读取两张 6000×4000 图，在 0/50/150/350ms 四档共 48 次均失败；失败后立即单次 `OpenClipboard` 的明确错误码均为 **5（拒绝访问）**。700/1500/3000ms 三档共 36 次均读到完整 PNG。旧报告没有识别打开失败被库吞掉的机制，也没有指出前置探测掩盖了等待，现予修正。
2. **3 秒可保留为本机的打开等待预算候选。** 12 次显式轮询均在首次序列变化后约 **553–614ms** 首次打开成功；全部浏览器样本中最后一次序列变化距菜单释放最晚约 **889ms**。本轮没有遇到浏览器持续占用超过 3 秒，但这不是所有机器、网站或 macOS 的上界。辅助进程持锁 3.5 秒时，3 秒预算后仍明确打开失败，应提示忙，不能转为无内容。
3. **200ms 不是完成判据。** 12 个不读取内容、不打开剪贴板的纯观察样本，都出现过“序列号静默 200ms、浏览器仍持有剪贴板、随后继续变化”；Edge 高熵图中两次连 500ms 静默也不是完成信号。200ms 可以作为重读的观察间隔候选，但必须结合显式打开、序列复核和再次读取；本实验没有实现完整六态流程，不能宣称该流程已通过。
4. **另有尚未发布的复制窗口。** 从菜单释放立即读时，18/18 次仍读不到 PNG，却能读到本实验预置的旧 `RapidRAW:adjustments` 标记；稍后均读到了本次图片。这是系统状态的实测，不是已复现应用错误套用。外部复制尚未更新系统剪贴板时，打开可能成功、序列号可能不变。新版 PLAN 6.4 已增加焦点后 500ms 保护（暂定）、单次打开加 50ms 重试，以及首次空/失败后隔 200ms 完整重读；这些是待实现和验收的设计，当前实验未验证焦点保护。后台写入和发布晚于 500ms 的机器仍是边界，不能将本项通过解释为正式粘贴安全性已通过。

`busy`、`failed` 不回退参数的计划保持必要；**不把 `get_buffer` 错误文本解析成 busy/none，也不把枚举为空当作无内容。**

## 环境、来源和计时

2026-11-06 至 2026-11-07，`pc.lan` Windows 10 x64 10.0.19045，已登录桌面 Session 1，AMD Ryzen 7 5800X3D。Rust/Cargo 1.99.1，`clipboard-rs = 0.3.5`，直接依赖既有同版本 `clipboard-win = 5.4.3`。Chrome 157.0.8103.38、Edge 156.0.4314.58。环境及清理核验见 [environment-cleanup.json](environment-cleanup.json)。

复用上轮的三张素材：`small.jpg` 1024×768；`large.jpg` 6000×4000 高熵生成图；`photo-control.jpg` 6000×4000 放大照片对照。后者来自仓库 2048×2048 照片，不是原生 24MP 相机照片。输入大小与 SHA-256 保存在原始 JSON，页面为本机 `http://127.0.0.1:8769/clipboard-contention.html`，不算真实网站覆盖。

每次复制前用 Win32 生成已知旧标记，模拟之前已复制调整参数的剪贴板状态；然后使用浏览器真实“复制图片/图像”菜单。早期样本以物理鼠标打开菜单，后续为避免 Edge 欢迎页/窗口干扰，使用绑定到素材标签的 CDP 可信 `contextmenu` 输入打开原生菜单；**触发复制的菜单选择始终使用真实 Win32 鼠标释放**。没有用 JS 写入 PNG 或模拟系统复制结果。

Rust release 读取器在点击菜单之前就启动并创建上下文。它先输出 `ready`，并以不打开剪贴板的观察线程记录序列号、当前打开窗口和所属 PID。每次必须重新复制，不把同一份内容的重复读取充当不同延迟样本。

- `direct` 的首个内容操作是 `get_buffer("PNG")`。之前没有格式枚举、文件、文本、`has()` 或显式打开；序列号和窗口查询不取内容、不加锁。
- `open-retry` 是独立对照：用 `clipboard_win::Clipboard::new()` 单次尝试，失败后每 50ms 再试，最多约 3 秒；保存真实 `Err(e).raw_code()`。不读取图片。
- `observe` 是独立纯观察对照，不打开或读取剪贴板。
- 直读失败后的显式打开、可选文本诊断都在 PNG 读取结束之后，不能算成读取之前的等待。库返回后的线程 last-error 仅作诊断，不作为失败阶段或内容类型判据。
- 观察持续到计时起点后约 3.4 秒；**完整 PNG 解码和摘要在观察结束之后执行**，再独立读取稳定 PNG 三次，核对来源、完整字节和像素。

QPC 计数器连接 Python 的菜单释放、Rust 的读取起止与观察事件。查询请求间隔为 1ms，实际受 Windows 调度影响；各 Win32 查询也不是原子快照。报告因此给出观测范围和打开失败/成功边界，不声称精确到 1ms 的连续锁时长。
